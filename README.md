# 写给你的情书

一个「程序员的情书」：左边是情书，右边是我们的时间轴。纯静态页面，零依赖、零后端，托管在 GitHub Pages 上。

左栏是**两封**：每人写一封，只写给对方看。你登录时看到的是 TA 写的那封；TA 登录时才看得到你写的。两个人各改各的，最后一键发布。

整站内容（文字 + 照片）都是**加密的**，没有口令打开只能看到一屏登录框，仓库里也没有任何明文。

---

## 打开它

线上地址：<https://zouajun.github.io/love-letter/>

打开后先选「你是谁」，再输口令：

| 账号 | 谁能进 |
| --- | --- |
| 小邹 | 用属于小邹的口令 |
| 小林 | 用属于小林的口令 |

勾上「在这台设备记住 7 天」，一周内再打开就不用重输了。换设备、清缓存、换浏览器都要重新输。

> 口令不保存在任何地方，只用来在本地解开钥匙。**忘了口令就等于内容没了**——两把钥匙都丢的话，我自己也救不回来。

## 本地预览

在项目目录里双击 `preview.bat`（Windows），会自动找一个空闲端口起服务并打开浏览器，地址形如 `http://127.0.0.1:8000/`。

也可以手动来：

```bash
python -m http.server 8000
# 然后访问 http://127.0.0.1:8000/
```

不能直接双击 `index.html`：浏览器不允许 `file://` 页面 fetch 本地文件，会白屏。

## 改内容

打开页面 → 输口令 → 点右下角「编辑」（或按 `Ctrl/⌘ + E`），三个页签：

- **情书**：你们的名字、在一起的日子、城市、配色、**你写的那封信**（标题/正文/署名）、封面图
- **时间轴**：逐条加/改/删记录、上传照片（每条最多 4 张）、隐藏不想要的自动纪念日
- **发布**：填一次仓库和 Token，之后点「提交到 GitHub」

「情书」页里改的永远是你自己那一封——左边显示给你看的是对方写的。对方那封还是空的时候，左栏会显示「这封还没写」和一个「写我这封」的按钮。

> 两封信都放在同一份 `content.enc` 里，用的是同一把钥匙——所以严格说是「默认不看对方的」，不是「技术上无法看」。要真做到互相隔离，得给每人单独一把钥匙，成本高很多。

改完点「完成」，改动会先存在这台设备的浏览器里（1 天内有效）。想上线就点「提交到 GitHub」，它会：

1. 把新选的照片压成 WebP 并加密，写成 `assets/photos/xxx.webp.enc`
2. 把整份内容加密成 `data/content.enc`
3. 以上所有文件合成**一个 commit** 推上去，中途失败不会留下半套内容

GitHub Pages 一般 1 分钟内自动更新。

**Token 怎么弄**：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens，只勾这个仓库，权限给 `Contents: Read and write`。Token 只存在你浏览器的 localStorage 里，不会写进仓库，也不会跟着页面发布出去。

**不联网的备用出口**：发布页里「导出 content.json」会把当前内容导出成明文 JSON（当备份用）。导出的文件**不要**直接传上仓库，那等于把密码撕了。

## 内容是怎么加密的

```
口令 ──PBKDF2(600000 次, 每人一个盐)──▶ 包裹钥匙(KEK)
                                          │
lock.json 里存的是：盐 + 用 KEK 加密过的内容钥匙
                                          ▼
                                   内容钥匙 K (AES-256)
                                          │
              ┌───────────────────────────┼───────────────────────────┐
              ▼                           ▼                           ▼
      data/content.enc          assets/photos/*.webp.enc        （一张一张）
      正文、日期、两封信                每张照片单独加密
```

- 算法：PBKDF2-HMAC-SHA256（60 万次）+ AES-256-GCM，全部用浏览器自带的 WebCrypto，没有第三方库。
- 每个密文文件都是一个 12 字节随机 IV 接一段密文（GCM 自带校验，改一个字节就解不开）。
- 两个账号各自有独立的盐，但解出来的是**同一把**内容钥匙——所以技术上两个人都能解开全部内容（包括对方那封信），界面上只是默认各看各的。
- 口令错的时候 GCM 校验直接失败，页面提示「口令不对」，不会泄露任何信息。

**能防什么**：陌生人拿到链接、翻仓库、看 Pages 的源文件，都只能看到密文；搜不到任何文字和照片。
**不能防什么**：设备被拿走且浏览器还记着登录（7 天内）；有人在你的浏览器里装脚本读内存；以及——口令本身太弱被离线爆破。所以口令别用生日和名字的组合。

## 照片

- 每张上传的图会先压到最长边 1400px、WebP，再加密。原文件超过 25MB 直接拒绝。
- 看图是浏览器解密后临时生成的 blob 地址，关掉页面就没了，不会留下明文文件。
- **滚到哪儿解到哪儿**：进页面只解密首屏看得见的一两张，往下滚才继续下载解密；等解密的位置先显示一层柔和的占位底色，出来之后淡入，不会出现破图标或「我们的照片」这类提示文字。
- 解出来的图存在浏览器本地（IndexedDB，最多 400 张，按使用时间自动清理）。同一台设备第二次打开、或者往下滚回来看过的图，不再走网络，直接出图。
- 点「提交到 GitHub」之外的任何时候清掉会话（清除 Token / 退出），本地缓存的明文图片会一并删除。
- 某张照片删掉后，对应的 `.enc` 文件不会自动从仓库删（避免误删），只是不再被引用，体积很小。

## 天数与纪念日

- 「第 N 天 / 在一起 N 天」都**包含开始那天**，所以在一起当天就是第 1 天。
- 自动纪念日：按设置里的天数和周年数自动排进时间轴，点「隐藏」可以单独去掉，随时恢复。
- 同一天既有手写记录又有自动纪念日时，只显示你写的那条，自动的让位（编辑器里会标注「当天已有手写记录」）。

## 目录结构

```
.
├── index.html              页面骨架 + 登录框
├── lock.json               ← 账号的盐和包好的钥匙（可以公开，口令不在里面）
├── preview.bat             双击本地预览（Windows）
├── preview.ps1             preview.bat 的实际逻辑
├── data/
│   └── content.enc         ← 加密后的全部内容
├── assets/photos/
│   └── *.webp.enc          ← 加密后的照片
├── css/
│   ├── base.css            变量、配色、左栏、登录框
│   ├── timeline.css        时间轴
│   └── editor.css          编辑抽屉
└── js/
    ├── app.js              启动、登录、渲染、计时
    ├── crypto.js           PBKDF2 / AES-GCM 封装
    ├── lock.js             解锁、会话、解密内容与图片（懒解密）
    ├── idb.js              解密后图片的本地缓存（IndexedDB）
    ├── content.js          数据结构、时间轴计算
    ├── date.js             日期工具
    ├── render.js           左右两栏的 HTML
    ├── editor.js           编辑抽屉
    ├── publish.js          加密 + 提交到 GitHub
    ├── github.js           Git Data API（一次提交）
    ├── store.js            草稿（1 天过期）
    ├── image.js            上传前压缩
    └── imgcache.js         明文模式的图片缓存（上锁后基本不用）
```

## 部署

仓库已经开了 Pages：`Settings → Pages → Deploy from a branch → main / (root)`。

以后改内容不用碰这个设置，编辑器里点「提交到 GitHub」就会自动重新部署。

换仓库/换账号的话：把整个目录推到一个新仓库，Pages 用同样方式打开，然后在编辑器「发布」页把仓库名改掉即可。

## 几句实话

- **Git 历史里还留着以前的明文**。加密是从现在这一版开始的，之前提交过的 `content.json` 和照片仍然能从历史里翻出来。要彻底清掉得重写历史（`git filter-repo` 之类），这件事需要单独确认后再做。
- 草稿存在浏览器 localStorage 里，是**明文**的，1 天后自动作废。
- 站点没有加 `noindex`，但 Pages 的默认域名本来也不会被搜索引擎收录；介意的话可以加一个 `robots.txt`。
